# P0b: Electron WebGL on GB10 (Oct 24, 2026, spark-2)

**Result: PASS, headless and on screen.** Electron 44.5.1 runs WebGL2 on the **GB10 GPU** (not SwiftShader) through ANGLE: headless (offscreen) and in a visible window on a GPU-backed GNOME 46 Wayland session reached over RDP. A 1080p viewer-like scene holds ~60 fps. **Remaining check:** the event box with its physical monitor (2 min at 08:30, same probe).

## Method
- Machine: spark-2 (DGX OS, aarch64, driver 580.178.04), boots to `multi-user.target`: no X/Wayland session, no Xvfb.
- Probe: `bench/ui_webgl_probe/` (`main.cjs`, `preload.cjs`, `page.html`); three.js 0.186.1 from the `nodehouse/` install. Scene: translucent icosphere "lung" (332,820 triangles, `depthWrite:false`) + emissive nodule sphere, `antialias:true`, 1920×1080, 240 frames. Reports `WEBGL_debug_renderer_info`, the frame-time median/p95, `app.getGPUFeatureStatus()`, and saves the last offscreen `paint` frame as PNG.
- Run (from a dir with the `nodehouse` install as `node_modules`):
  `TAG=vulkan ./node_modules/electron/dist/electron --no-sandbox --ozone-platform=headless --ozone-override-screen-size=1920,1080 --use-angle=vulkan main.cjs`
  (`--no-sandbox` only because `chrome-sandbox` isn't root-owned here; it doesn't affect the GPU path.)

## Results

| ANGLE backend | WebGL renderer | Frame ms median / p95 |
| --- | --- | --- |
| `--use-angle=vulkan` | `ANGLE (NVIDIA, Vulkan 1.4.312 (NVIDIA NVIDIA GB10 (0x00002E12)), NVIDIA)` | 16.7 / 16.8 |
| `--use-angle=gl-egl` | `ANGLE (NVIDIA Corporation, NVIDIA GB10/PCIe, OpenGL ES 3.2)` | 16.7 / 16.8 |
| default (no flag) | GPU process fails: ANGLE's EGL tries to open an X display that doesn't exist → page never renders (timeout) | — |

Frames are capped by `setFrameRate(60)`, so 16.7 ms means "at least 60 fps"; actual headroom wasn't measured. Feature status: `webgl: enabled`, `gpu_compositing: enabled`, `opengl: enabled_on`. Frame PNGs (1920×1080, scene visible) were checked by eye.

## On-screen run (GNOME desktop over RDP, same evening)

spark-2 has no monitor, so the GNOME desktop was reached through GNOME Remote Desktop's headless "remote login": RDP over Tailscale, which gives a virtual 1920×1080 monitor. The session log confirmed `Created gbm renderer for '/dev/dri/card0'`, i.e. the desktop itself is drawn on the GPU. The probe ran as test user `sparkmd` (see setup below) with `ONSCREEN=1`, the `chrome-sandbox` fix applied, and **no `--no-sandbox`**. Window clamped to 1854×982 by the desktop's work area; the canvas stays 1920×1080.

| Run | WebGL renderer | Frame ms median / p95 |
| --- | --- | --- |
| default (native Wayland) | `ANGLE (NVIDIA Corporation, NVIDIA GB10/PCIe, OpenGL ES 3.2)` | 16.8 / 38.5 |
| `--use-angle=vulkan` | `ANGLE (NVIDIA, Vulkan 1.4.312 (NVIDIA GB10))` | 17.1 / 22.2 |
| `--use-angle=gl-egl` | `ANGLE (NVIDIA Corporation, NVIDIA GB10/PCIe, OpenGL ES 3.2)` | 16.7 / 24.2 |
| `--ozone-platform=x11` (XWayland) | `ANGLE (NVIDIA Corporation, NVIDIA GB10/PCIe, OpenGL 4.5.0)` | 16.7 / 16.8 |

All four: `webgl: enabled`, `gpu_compositing: enabled`, scene visible in the screenshot. One run each, so the p95 differences (startup frames, RDP encoding) are noise until repeated. **Choice:** on a desktop the default already uses the GPU. Pin `use-angle=gl-egl` in the Electron main anyway, because it's the same renderer the default picks *and* it also works headless. Keep `--ozone-platform=x11` as the fallback if the viewer stutters on the event box.

### Remote-desktop setup on spark-2 (for testing UI on a GB10 without a monitor)
- `sudo grdctl --system rdp set-tls-key/-cert` (self-signed, `openssl req … -days 30`, files in `/var/lib/gnome-remote-desktop/`), `set-credentials <user> <pw>`, `rdp enable`; `sudo systemctl start gdm` (start, not enable: the box still boots to `multi-user.target`).
- **Changing RDP credentials needs `sudo systemctl restart gnome-remote-desktop`**, or the old ones stay in effect (logon failure).
- **`/tmp/.X11-unix` and `/tmp/.ICE-unix` must be `root:root`.** On a box that never ran a desktop, gdm creates them as `gdm:gdm`, and the user's GNOME Shell crashes (`Failed to start X Wayland: Wrong ownership`) → blank RDP screen after login.
- **A remote (seatless) session only gets the GPU if the user is in `video` + `render`.** Otherwise mutter logs `Created surfaceless renderer without GPU` (software). `ty` isn't in those groups, and its user systemd manager hosts `nemoclaw-openshell-gateway.service`, so adding groups would mean bouncing it. Hence the test user: `useradd -m -G video,render sparkmd`.
- Client (laptop): `sdl-freerdp3 /v:ty-dgx-spark-2.tail29ed60.ts.net /u:<rdp-user> /size:1920x1080 /cert:ignore`; then log in as `sparkmd` at the GDM screen.
- Teardown: `sudo grdctl --system rdp disable && sudo systemctl stop gnome-remote-desktop gdm`; `sudo userdel -r sparkmd`.

## Gotchas found
- **Shown windows crash under `--ozone-platform=headless`** (segfault, even with `--disable-gpu`). Use `webPreferences.offscreen: true` + `show:false` for headless tests.
- **Headless screen defaults to 1×1:** without `--ozone-override-screen-size=1920,1080`, offscreen `paint` frames are 1×1 (the WebGL drawing buffer is still full size).
- `capturePage()` returns an empty image in offscreen mode; grab the `paint` event's image instead.
- Mesa's freedreno Vulkan ICD logs `VK_ERROR_INCOMPATIBLE_DRIVER` on `/dev/dri/renderD128`. Harmless: the loader then picks `nvidia_icd.json`.
