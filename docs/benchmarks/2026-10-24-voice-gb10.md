# Voice bake-off: ASR + TTS on GB10 (Oct 24, 2026, spark-2 + laptop)

**Result.** ASR pick is **whisper.cpp `ggml-small.en`, CUDA, phrase prompt + Silero VAD**: 337/339 correct, **0 wrong commands**, 74 ms median / 125 ms p95 per 2–3 s clip on GB10 (151 / 254 ms while the LLM decodes). TTS: **faster-qwen3-tts (Qwen3-TTS 1.7B-Base, voice clone) in `martinb78/faster-qwen3-tts-dgx-spark:v6.15.0`**: ~0.68 s to first audio, 0.67× real time, ~5.4 GB GPU, but **1.9–2.1 s first audio and 1.4–1.9× real time (choppy if streamed) while the LLM decodes**.

**Caveat: every clip is synthetic** (Qwen3-TTS CustomVoice, 7 built-in speakers). No human voice tested yet; see "Still to do".

## Method
- Clip set (`bench/voice/phrases.py`): 11 positives over the 4 commands (canonical + paraphrases, e.g. "Why'd you flag this one?", "Reset view.") + 4 spoken negatives ("Approve the report.", "Go to the next patient.", "Can everyone hear me okay?", "This is a solid nodule in the right upper lobe."). 7 speakers (aiden, dylan, eric, ryan, serena, uncle_fu, vivian) → 105 clips, padded 0.25 s each side, 16 kHz mono.
- Variants (`mkvariants.py`): **clean**; **babble** (two overlapping chatter tracks built only from the negative clips, at −8 dB SNR); **far** (−12 dB gain + 60 Hz hum + noise floor); **empty** (24 clips: noise floor, brown noise + 120 Hz hum, chatter-only; i.e. push-to-talk pressed while nobody says a command). n = 339.
- Score = transcript → `matcher.py` (stdlib `difflib` ratio against the command phrase list after normalising; accept if best ≥ 0.80 and best − second ≥ 0.08) == expected command (or `None` for negatives). "Wrong command" = a command fired that wasn't asked for (worse than a miss).
- Latency = wall time of one request on a warm model (whisper.cpp via `whisper-server` HTTP `/inference`, the others in-process), 2–3 s clips.
- Machine: spark-2 (GB10, DGX OS, driver 580.178.04), TensorFold Qwen3.8-27B resident and idle unless noted; laptop = RTX 3080. Raw rows: `2026-10-24-voice-asr-gb10.raw.jsonl` (field `run`).
- whisper.cpp commit `231638a` (Oct 19, 2026), built with `-DGGML_CUDA=1 -DCMAKE_CUDA_ARCHITECTURES=121`.

Findings:
- **The phrase prompt is the biggest win** (+4–10 clips per variant), **but it makes whisper hallucinate the prompt on noise**: small.en printed "Why did you flag this?" for 7/8 brown-noise clips → would fire a command when push-to-talk is pressed by accident. **Silero VAD (`--vad`) removes it** (0/24) at +30 ms. Keep prompt and VAD together.
- **No GPU path on aarch64 for faster-whisper or Parakeet-ONNX**: PyPI `ctranslate2` 4.8.3 aarch64 reports 0 CUDA devices; `onnxruntime` 1.31.0 aarch64 is CPU-only. whisper.cpp builds with CUDA from source (build time not measured; time it in the dry run).
- ~4 of the clean misses are bad TTS clips (e.g. vivian "Show me the nodule, please" heard by every engine as "You need a nodule, please"), so clean accuracy is a floor.
- Matcher threshold barely matters with the prompt (0.70–0.80 give the same result for base.en/small.en+VAD); with large-v3-turbo + prompt, 0.70 lets 5 wrong commands through, so keep 0.80.
- Memory: `whisper-server` small.en ≈ 0.86 GB GPU + 0.28 GB RSS.
- Laptop (3080, same clips without "empty"): whisper.cpp base.en+prompt 16 ms, small.en+prompt 33 ms, turbo 80 ms; same accuracy pattern. faster-whisper on the laptop failed on CUDA (wants `libcublas.so.12`; the laptop has CUDA 13): irrelevant for the box.

Server: `martinb78/faster-qwen3-tts-dgx-spark@sha256:ee83531abd5df4aa11f165110703bfd7d581d7d59c42e58a429c919b35d5f072` (tag `v6.15.0`, arm64, torch 2.12.1+cu130, transformers 4.57.6, faster-qwen3-tts 0.2.6), model `Qwen/Qwen3-TTS-12Hz-1.7B-Base` (voice clone; the image's server only does voice clone).
